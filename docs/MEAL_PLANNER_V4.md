# 献立エンジン v4

生活スケジュールと担当者適性を加味した献立提案です。v3（栄養・アレルギー・体調・在庫）は維持し、上に生活レイヤを載せます。

## 入口

- `optimizeWeeklyMealPlanV4` / `optimizeDayMealV4`
- UI: `/meals`（提案プレビュー → 採用）

スケジュールが無い曜日は内部で `optimizeDayMeal`（v3）へフォールバックします。

## ハード制約（候補から除外）

1. アレルギー・食事制限（常に最優先）
2. 固定献立・入力済みの日
3. 外食 / 献立不要（DailyCookingOverride）
4. 担当者が作れない調理法・avoid 設定
5. 曜日の調理時間・工程数上限
6. 揚げ物禁止日
7. 初心者担当日の上級（hard）料理
8. レシピ側の担当指定に含まれない場合

## スコアリング（重み変更。数値は UI に出しません）

- 担当者の作りやすさ・得意・作り慣れた料理
- 曜日の手間・洗い物・作り置き・新しい料理可否
- 買い出し日の候補拡張 / 買い出し日以外の買い足し抑制
- 週内の食材再利用
- 栄養・体調・在庫・頻度・好みなど（v3 系）

## 生成モード

既存モードに加え、生活向けモードをスコア重みとして追加:

生活優先 / 担当者優先 / 作り慣れた料理優先 / 新しい料理に挑戦 / 買い足し最小 / 週末に手の込んだ料理 / 娘でも作りやすい

アレルギー等のハード制約はモードでも解除されません。

## 理由表示

内部スコアは出さず、日本語の短い理由に変換します。例:

- 夫が担当するため、30分以内で作り慣れた料理を優先しました
- 娘さんが作りやすい料理です
- 買い足しが少なくなる組み合わせです

## パフォーマンス

- 提案生成はボタン操作時のみ（毎 render 再計算しない）
- 二重実行防止フラグ
- 生成中表示
- 事前にハード制約で候補を絞り込み
